### v5.1 (not yet released)

The runner function `exit_code()`, which runs the suites and ends the
session, is deprecated in favour of `run()`, which does the same and
returns the same exit code; `exit_code()` is still available, as an
alias of `run()`. The session now runs only once: later calls of
`run()` return the same exit code without running the suites again, and
a second `initialise()` is reported and ignored.

The integer literals now follow the C++ syntax: `0x`, `0b`, and
leading-`0` (octal) prefixes are parsed, so `010_i` is 8 (it was 10),
and a decimal point, or a value that does not fit in the type of the
literal (e.g. `300_u8`, or `-128_i8`, whose absolute value does not
fit), is now a compilation error.

The relational comparisons (`<`, `<=`, `>`, `>=`, `lt()`, `le()`, `gt()`,
`ge()`) now apply the tolerance of the floating-point literals and
wrappers, as `==` and `!=` already did: values within the tolerance are
equal, so `1.45 < 1.5_d` is now false, and `1.45 <= 1.5_d` true. The new
`mt::approx (value, epsilon)` sets the tolerance explicitly.

The comparators now compare the C strings (`char` arrays, string
literals, and `char` pointers) by content, as `std::string_view`, also
with `std::string`; two `const char*` holding equal strings were
previously compared by address. To compare the addresses, cast the
pointers to `const void*`. The pointer overloads of the comparators
were removed; the generic ones handle all the pointers.

The `expression_formatter` and the reporters now write the non-const
`char` pointers and arrays as strings, as they write the `const char`
pointers; they were previously written as addresses. A null `char`
pointer is written as `nullptr`.

An exception that escapes the body of a test case is now reported as a
failed check, at the location of the `test()` call, and the run
continues with the next test case; it previously ended the program. To
capture that location, the name parameter of `suite::test()` and
`subtest::test()` is now a `detail::test_name`, converted implicitly
from a string literal or a `const char*`; an argument that converts to
`const char*` only via a user-defined conversion operator must now be
converted explicitly. As for `expect()`, GCC with `-Waggregate-return`
now warns at the `test()` calls too.

### v4.1 (2026-05-12)

Passing the top suite name via the runner constructor is deprecated in
favour of passing it via the `initialise()` function. The name is
optional; the default is the program name, derived from `argv[0]`.

### v4.0 (2026-04-20)

Major rework introducing explicit objects for test suites and test cases
(subtests), using a `ts.test()` and `t.expect()` mechanism inspired by
[node-tap](https://node-tap.org). Internal static objects are no longer used.
The TAP reporter is now the default.

### v3.3 (2026-03-22)

Support for multiple reporters was added, including a new TAP-compliant
reporter.

### v3.0 (2022-04-03)

Significant revision introducing a comprehensive set of comparators, exception
handling, function templates for test cases, and class templates for test
suites. Heavily influenced by [Boost UT](https://boost-ext.github.io/ut/).

### v2.3.0 (2022-02-19)

The `run_test_case(func, name)` function was deprecated in favour of
`run_test_case(name, func)`, in preparation for the adoption of variadic
templates.

### v2.0 (2021-03-01)

The C++ namespace was changed from `os` to `micro_os_plus`.

### v1.0 (2021-02-04)

The initial codebase, noted for its simplicity and inspired by
[node-tap](https://node-tap.org), was extracted from the µOS++ monorepo.
