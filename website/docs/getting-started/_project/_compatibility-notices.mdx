### v5.1 (not yet released)

The runner function `exit_code()`, which runs the suites and ends the
session, is deprecated in favour of `run()`, which does the same and
returns the same exit code; `exit_code()` is still available, as an
alias of `run()`. The session now runs only once: later calls of
`run()` return the same exit code without running the suites again, and
a second `initialise()` is reported and ignored.

The integer literals now follow the C++ syntax: `0x`, `0b`, and
leading-`0` (octal) prefixes are parsed, so `010_i` is 8 (it was 10),
and a decimal point, or a value that does not fit in the type of the
literal (e.g. `300_u8`), is now a compilation error. The minimum of a
signed type can be written with the unary minus (`-128_i8`), but its
absolute value alone (`128_i8`) cannot be used.

The negation of an integer literal now keeps the type of the literal:
`-1_i8` and `-1_s` were previously of type `int`, and `-1_u8` was the
`int` value -1. The negation of an unsigned literal now wraps around
for all the types, as it already did for `-1_u` (`UINT_MAX`), so `-1_u8`
is the `std::uint8_t` value 255, and `mt::eq (-1_u8, -1)` now fails.
The negation of the minimum of a signed type (`-(-128_i8)`) is a
compilation error.

With `--quiet`, the TAP reporter now displays one `ok`/`not ok` line per
test suite, followed by the plan of the session (`1..N`) and the totals.
The plan was previously `1..0`, which the TAP consumers (for example
node-tap) read as a run with all tests skipped, so as successful, even
when tests failed.

In the `ok`/`not ok` lines of the TAP output, the `#` and `\`
characters of the names, the messages, and the expressions are now
escaped (`\#` and `\\`), as the TAP 14 specification recommends, and
the line breaks are replaced by spaces. Previously, a `#` in a name
could start a directive, so a failed test case named
`parser # TODO rework` was read by the TAP consumers as a `TODO`, and
not counted as failed, and a line break in a message broke the line.
The consumers remove the escapes, so the names they report are
unchanged; tools that read the TAP lines as plain text now see the
escapes.

The relational comparisons (`<`, `<=`, `>`, `>=`, `lt()`, `le()`, `gt()`,
`ge()`) now apply the tolerance of the floating-point literals and
wrappers, as `==` and `!=` already did: values within the tolerance are
equal, so `1.45 < 1.5_d` is now false, and `1.45 <= 1.5_d` true. The new
`mt::approx (value, epsilon)` sets the tolerance explicitly.

The tolerance of the floating-point wrappers (`mt::to_f`, `mt::to_d`,
and `mt::to_ld`) is now one unit of the last decimal of the value, as
documented, for all values. Previously, the rounding of many values
(e.g. `mt::to_d{ 0.011 }`) produced 17 or 18 decimals, so they were
compared almost exactly, and a negative value (e.g. `mt::to_d{ -1.5 }`)
gave an undefined tolerance. Such comparisons may now give a different
result: `mt::lt (0.0105, mt::to_d{ 0.011 })` is now false, since the
values are within the tolerance of 0.001. To compare exactly, use
`mt::approx (value, 0.0)`, or a plain floating-point value.

The leading zeros of a small wrapped value are now counted as decimals:
previously, every value up to `1e-8`, and zero, got a tolerance of 0.1,
so `mt::eq (mt::to_d{ 1e-12 }, 0.05)` passed. Now `mt::to_d{ 1e-12 }`
has a tolerance of 1e-12, and a zero (`mt::to_d{ 0.0 }`) compares
exactly, so `mt::eq (mt::to_d{ 0.0 }, 0.09)` fails; the literal
`0.0_d` keeps the tolerance of its written decimal, 0.1. Comparisons of
such values may now fail; to keep a wider tolerance, use
`mt::approx()`.

The comparators now ignore the members named `value` and `epsilon` of
the application types, which only identify the numeric literals and
the floating-point wrappers of the framework, and compare such types
with their own operators. Previously, a type with a data member named
`value` could not be compared (a compilation error), and a type with a
member named `epsilon` was compared with that member as a tolerance.

The comparators now compare the C strings (`char` arrays, string
literals, and `char` pointers) by content, as `std::string_view`, also
with `std::string`; two `const char*` holding equal strings were
previously compared by address. To compare the addresses, cast the
pointers to `const void*`. The pointer overloads of the comparators
were removed; the generic ones handle all the pointers.

The `expression_formatter` and the reporters now write the non-const
`char` pointers and arrays as strings, as they write the `const char`
pointers; they were previously written as addresses. A null `char`
pointer is written as `nullptr`.

In the failure messages, the `signed char` values are now written with
the `sc` suffix (`5sc`), and the `long double` values with the `ld`
suffix (`1.5ld`), the names of the `_sc` and `_ld` literals; they were
previously written with `c` and `l`, which suggest `char` and `long`.
The floating-point values with an integral value are now written with a
decimal point (`42.0`, `42.0f`, `42.0ld`), so that they can be
distinguished from the integers; they were previously written as `42`
and `42f`. The messages added with `<<` are unchanged.

The `char` values are now written as quoted character literals, with
the non-printable characters escaped (`'a'`, `' '`, `'\0'`, `'\x1b'`);
they were previously written raw, so a space was invisible, and a zero
character hid the rest of the output of the test case. This also
applies to the `char` values written by the application `operator<<`
functions to the `expression_formatter`; to write a separator without
quotes, use a string (`" "` instead of `' '`). A zero character in a
message added with `<<` no longer ends the message.

The `expression_formatter` can now only be appended to, through its
`operator<<` overloads, and read, through `str()`. The buffer
accessors `c_str()`, `clear()`, `empty()`, `append()`, and
`reserve()`, which the framework did not use, were removed, and the
functions that assign the buffer to the checks are private, so that an
application `operator<<` cannot alter the texts of the pending checks.
Use `str().c_str()` and `str().empty()` instead of the removed
functions.

Where `long double` is wider than `double` (e.g. x86-64 Linux and
macOS, AArch64, and RISC-V), the `long double` values are now written
in the shortest form that reads back as the same value, as the `float`
and `double` values are; they were previously written with six
significant digits, so `0.1L` and `0.1000001L` were both written as
`0.1ld`. A value converted from `double` may now show the digits of
its conversion error (`static_cast<long double> (42.42)` is written as
`42.420000000000001705ld` on x86-64). Where the C library formats
`long double` with the precision of `double` (e.g. newlib on AArch64
and RISC-V), the values are written in the shortest form of their
conversion to `double`.

The named boolean constants created by the `_b` literal can now be
used in the checks; any check that used them previously overflowed
the stack. They are reported by their name (`"flag"_b == flag` fails
as `flag == false`), and, with the operators in the `operators`
namespace, `==` and `!=` now return a comparator, as for the other
literals, instead of a plain `bool`. The literal now returns a
`detail::named_bool`, which no longer derives from `std::string_view`;
`name()` returns the name.

The `==` and `!=` operators for `std::string_view` were removed from
the `operators` namespace; the standard operators are now selected, and
return a plain `bool`, so a failed `t.expect (sv == "abc"sv)` no longer
shows the operands. Previously, after `using namespace mt::operators`,
every comparison of a `std::string_view` with a `std::string_view`, a
`std::string`, or a C string, also in the application code, returned a
comparator instead of a `bool`, while the comparisons of two
`std::string` objects, or of a `std::string` and a C string, returned a
`bool`. Use `mt::eq()` and `mt::ne()` to compare strings.

An exception that escapes the body of a test case is now reported as a
failed check, at the location of the `test()` call, and the run
continues with the next test case; it previously ended the program. To
capture that location, the name parameter of `suite::test()` and
`test_case::test()` is now a `test_case_name`, converted implicitly
from a string literal, a `const char*`, or a `std::string` (which was
previously not accepted); an argument that converts to `const char*`
only via a user-defined conversion operator must now be converted
explicitly. Helper functions that add test cases can take a
`const test_case_name&` parameter, so that the reported location is
that of their caller.

The name parameter of `runner::suite()` is now a `std::string_view`, so
a `std::string` is also accepted; as for `test()`, an argument that
converts to `const char*` only via a user-defined conversion operator
must now be converted explicitly. As for `expect()`, GCC with `-Waggregate-return`
now warns at the `test()` calls too.

Likewise, an exception that escapes the body of a test suite, outside
its test cases, is now reported as a failed check of that suite,
without a source location, and the run continues with the next suite;
it previously ended the program, without the final totals. As for the
test cases, the suite body must not be `noexcept` for the exception to
be caught.

A test case started on the suite (`ts.test()`) from the body of a
running test case, for example via a captured suite reference, now runs
nested in the running test case, as if started with `t.test()`. After a
check, it previously aborted the program; before any check, the report
was malformed.

The counters and the indices of the runner, the suites, and the test
cases can no longer be modified by the user code: `totals()` now
returns only a `const` reference, so a reference that stores its result
must be `const`, and the `own_index (size_t)` setter and
`increment_subtest_index()` are no longer public. The read-only
`totals()` is still available.

The functions of the suites and the test cases that serve only the
runner and the reporters are no longer public: `run()`, which ran the
node again and reported it twice, `abort()`, and the read-only
`own_index()`, `children_subtests_count()`, and
`current_subtest_index()`, used only for the TAP output. The
`name (const char*)` setter of the top suite, which could not be
reached, since `initialise()` returns a `suite&`, was removed. Call
`runner::abort()` to abort the test execution, and `totals()` to read
the counters of a node; the name of a node is still returned by
`name()`.

The constructors of `test_case`, `suite`, and `top_suite` are no longer
public, since a suite or a test case constructed directly was neither
registered nor run. Create the suites with `runner::suite()` or as
`static_suite` objects, and the test cases with `test()`.

The `detail::runner_totals` class, returned by `totals()`, is now
`micro_os_plus::micro_test_plus::counters`, since the suites and the
test cases own one too, not only the runner; its `was_successful()`
function is now `passed()`. The old names are not kept; replace
`detail::runner_totals` with `counters`, and `was_successful()` with
`passed()`. The `timings()` functions
of the runner and of the suites, and the `expression()` function of the
reporters, were removed, since they return internal types and are used
only by the framework.

The reporters (`reporter`, `reporter_human`, and `reporter_tap`) and the
`endl` and `indent()` manipulators moved to the `detail` namespace,
since they are internal to the framework and custom reporters are not
supported; the reporter is still selected with the `--reporter`
command-line option. `runner::reporter()` was removed; replace
`runner.reporter ().verbosity ()` with the new `runner.verbosity ()`.

The runner can now be initialised without a command line, with a new
`initialise (options, name)` overload taking a `runner_options`
structure (the reporter, the verbosity, and the output file), so the
applications without command-line arguments no longer need to build an
`argv` array; `initialise (argc, argv, name)` parses the command line
into the same structure.

The option errors (an unknown `--reporter` name, a missing option
argument, or an output file that cannot be opened) no longer terminate
the program: they are reported on `stderr`, the option is ignored, the
tests are run, and `run()` returns 2. The new
`runner::set_abort_handler()` can replace the final `::abort()` call
when the test execution is aborted, for example to reset an embedded
target.

`assume()` is deprecated in favour of `require()`, which does the same:
in other frameworks (JUnit, Hypothesis), an unmet assumption skips the
test, while here it fails it. When exceptions are enabled, a failed
`require()` (or `assume()`) now stops only the current test case, as
`ASSERT_*` in GoogleTest, `REQUIRE()` in Catch2 and doctest, and
`BOOST_REQUIRE()` in Boost.Test do, and the run continues with the next
test case; it previously aborted the program, without the final
totals. The test case is stopped with an exception not derived from
`std::exception`, so a test case body that calls `require()` must not
be `noexcept`, and a `catch (...)` in it must rethrow. Without
exceptions, a failed `require()` still aborts the test execution, but
the report written before the abort is now complete: the results of
the aborted test case are displayed after its name, which the human
reporter previously omitted with normal and quiet verbosity, so that
the failure appeared under the previous test case; they are now also
written to the output file, which previously ended before them, and
they are no longer displayed with silent verbosity. The TAP reporter
now ends the output with a
`Bail out! Requirement failed at <file>:<line>` line.

A failed requirement is no longer marked as `aborted...`, which was
inaccurate with exceptions, since only the test case is stopped. The
human reporter now names the effect that follows, `- test case stopped`
or, without exceptions, `- test execution aborted`. The TAP reporter
reports it like any other failed check, as node-tap does: the marker
was written inside the YAML diagnostics block, either after the
opening `---`, which the TAP consumers then did not recognise, or at
the end of the `condition:` value.

In the YAML diagnostics blocks of the TAP output, the `condition:`
values are now written as YAML double-quoted scalars, with `\`, `"`,
and the control characters escaped (`condition: "1 == 2"`). They were
previously written as plain scalars, so the values that start with `{`
or `'` (the container and the `char` operands, e.g. `{1, 2} != {1, 2}`
or `'\0' == 'a'`), or contain `: `, were rejected by the YAML parsers
of the TAP consumers, which then reported the failed test point without
any diagnostics, and a value that contains ` #` was truncated. The
consumers remove the quotes and the escapes, so the values they report
are unchanged; tools that read the TAP lines as plain text now see
them.

In the `at:` field of the YAML diagnostics blocks, the location of a
failed check is now written as `fileName:` and `lineNumber:`, as
node-tap writes it; it was previously written as `filename:` and
`line:`. The node-tap reporters read the file name only from
`fileName:` (or `file:`), so the file name was lost, for example in the
JUnit report, where the failed test case had neither the `file` nor
the `line` attribute that the CI systems use to annotate the failure.
Tools that read the previous names must be updated.

The runner no longer derives from the internal `detail::test_node`
class, since it is not a node of the test tree: `runner::name()`, which
always returned `"runner"`, was removed; the name shown in the reports
is that of the top suite, returned by `initialise()`. The session
totals are still available, via `runner::totals()`.

The callable of a `static_suite` now receives a `suite&` reference, as
the callable of a suite registered with `runner::suite()` does, so the
same function can serve both kinds of suites; it previously received a
`static_suite&`. Replace `mt::static_suite&` with `mt::suite&` in the
parameter lists of the suite functions; the lambdas with an `auto&`
parameter need no change.

The additional arguments of `test()`, `runner::suite()`, and the
`static_suite` constructor are now stored by a lambda, instead of
`std::bind`, which adds less code. They are still copied, so a
reference parameter refers to the copy, but a `std::ref()` argument is
no longer unwrapped: it still converts to a parameter of type `T&`, but
an `auto&` parameter now receives the `std::reference_wrapper` itself;
call its `get()` function, or pass a pointer instead.

The `static_runner` class is deprecated, and is now an alias of
`runner`, since any runner also runs the `static_suite` objects that
refer to it; the static suites are kept in a list independent of the
runner object, so they may be constructed before it, in any order. The
existing code compiles unchanged; replace `mt::static_runner` with
`mt::runner` in the new code. The public static member
`static_runner::register_static_suite()` was removed;
`runner::static_suites_count()` is now available for any runner.

The `runner()` function of the suites and the test cases, which
returned the runner that owns them, is no longer public, since it is
used only by the framework; it was renamed, so that it no longer hides
the `runner` class in the derived classes. A test function that needs
the runner can capture it, or receive it as an argument.

The `subtest` class is renamed `test_case`, the term used by the
documentation and by the reports, and the functions named after it are
renamed accordingly; the old names are not kept. Replace `mt::subtest`
with `mt::test_case`; the lambdas with an `auto&` parameter need no
change. In `counters`, `executed_subtests()` is now
`executed_test_cases()`, next to the new `failed_test_cases()` and
`skipped_test_cases()`. The output of the reporters is unchanged; the
TAP reporter still introduces each test case with a `# Subtest:` line.

The logical functions `_and()`, `_or()`, and `_not()` are renamed
`both()`, `either()`, and `negate()`, since a leading underscore is not
used by the other public names, and `and`, `or`, and `not` are
alternative tokens; the old names are not kept. The overloaded `&&`,
`||`, and `!` operators are unchanged.

The type wrappers deprecated in v3.2 were removed: the `_b`, `_c`,
`_sc`, `_s`, `_i`, `_l`, `_ll`, `_u`, `_uc`, `_us`, `_ul`, `_ull`,
`_i8`, `_i16`, `_i32`, `_i64`, `_u8`, `_u16`, `_u32`, `_u64`, `_f`,
`_d`, and `_ld` aliases, and the generic `_t<T>` wrapper. Replace them
with the `to_*` forms, which take the same arguments: `mt::_i (expr)`
becomes `mt::to_i (expr)`, and `mt::_t<T>{ expr }` becomes
`mt::to_t<T>{ expr }`. The literals with the same suffixes (`42_i`,
`1.5_d`) are unchanged.

The `get()` function of the `to_*` wrappers and of the integer literals
now returns a `const` reference to the wrapped value, instead of a copy,
so that the comparators no longer copy the operands each time they
compare or report them. A reference that stores its result is valid
only as long as the wrapper: in
`const auto& s = mt::to_t<std::string>{ str }.get ();`, `s` refers to a
destroyed temporary. Store the result by value (`auto s = ...`) instead.

The deprecated entities, previously marked as such only in the
documentation, now carry the `[[deprecated]]` attribute, so the
compiler warns where they are used: the runner constructor with the top
suite name (deprecated in v4.1), `exit_code()`, `assume()`, and
`static_runner`. They still work as before, but a build with `-Werror`
now fails. Replace them with, respectively, the constructor without
arguments followed by `initialise (argc, argv, name)`, `run()`,
`require()`, and `runner`.

The helpers not used by the framework were removed: `mut()`, and the
`type_traits::list`, `type_traits::identity`, and
`type_traits::function_traits` templates. Code that used them must
define its own equivalents; `mt::mut (x)` is `const_cast<T&> (x)`, and
`std::type_identity` (C++20) replaces `type_traits::identity`. The
utility functions `utility::is_match()` and `utility::split()` are
unchanged.

### v4.1 (2026-05-12)

Passing the top suite name via the runner constructor is deprecated in
favour of passing it via the `initialise()` function. The name is
optional; the default is the program name, derived from `argv[0]`.

### v4.0 (2026-04-20)

Major rework introducing explicit objects for test suites and test cases
(subtests), using a `ts.test()` and `t.expect()` mechanism inspired by
[node-tap](https://node-tap.org). Internal static objects are no longer used.
The TAP reporter is now the default.

### v3.3 (2026-03-22)

Support for multiple reporters was added, including a new TAP-compliant
reporter.

### v3.0 (2022-04-03)

Significant revision introducing a comprehensive set of comparators, exception
handling, function templates for test cases, and class templates for test
suites. Heavily influenced by [Boost UT](https://boost-ext.github.io/ut/).

### v2.3.0 (2022-02-19)

The `run_test_case(func, name)` function was deprecated in favour of
`run_test_case(name, func)`, in preparation for the adoption of variadic
templates.

### v2.0 (2021-03-01)

The C++ namespace was changed from `os` to `micro_os_plus`.

### v1.0 (2021-02-04)

The initial codebase, noted for its simplicity and inspired by
[node-tap](https://node-tap.org), was extracted from the µOS++ monorepo.
