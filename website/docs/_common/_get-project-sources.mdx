## Obtain project sources

The **@micro-os-plus/micro-test-plus** project is hosted on GitHub:

- https://github.com/micro-os-plus/micro-test-plus-xpack.git

<BranchesDetails />

<Tabs groupId="clone">

<TabItem value="fork" label="Use Fork" default>

To contribute **Pull Requests**, fork the project. For this, go to the
GitHub project page and click on the
**[Fork](https://github.com/micro-os-plus/micro-test-plus-xpack/fork)**
button.

:::tip

To get the all branches of the repository, be sure to **disable** the
**Copy the xpack branch only** button in the fork dialog.

:::

After creating the fork, the next step is to **clone the forked repository**:

```sh
USER_ACCOUNT_ID=<your-account>
```

```sh
rm -rf ~/Work/micro-os-plus/micro-test-plus-xpack.git && \
mkdir -p ~/Work/micro-os-plus && \
git clone \
  --branch xpack-development \
  https://github.com/${USER_ACCOUNT_ID}/micro-test-plus-xpack.git \
  ~/Work/micro-os-plus/micro-test-plus-xpack.git
```

:::tip

After making changes, be sure to direct the Pull Requests to the
`xpack-development` branch, otherwise it may be rejected.

:::

</TabItem>

<summary>Add links for development</summary>

By default, to prevent inadvertent changes, xpm dependencies are
installed in read-only folders with filtered content; developer-related
files are not installed

However, during development, it is convenient to maintain a writable
instance of the code to enable changes in parallel with the parent
project.

Therefore, during development, if this project is used as a dependency
of another project, it is convenient to use the full version of the
project and make changes directly in the local development folder.

The mechanism xpm uses for this is called _linking_, and is similar
to the npm link mechanism.

The process has two steps:

1. Tell the global xpm configuration where the local development
   folder is located.
2. Tell the top project to use the linked development folder
   instead of the installed read-only dependency.

The first step requires executing the `xpm link` command in the
local development folder, as shown below:

```sh
xpm link -C ~/Work/micro-os-plus/micro-test-plus-xpack.git
```

The result is the creation of a symbolic link in the global xPacks
store pointing to the local development folder.

For example:

```console
% ls -l xPacks/micro-os-plus/micro-test-plus-xpack/.link
lrwxr-xr-x  1 ilg  staff  75 Oct 26 21:57 xPacks/micro-os-plus/micro-test-plus-xpack/.link -> /Users/ilg/Work/micro-os-plus/micro-test-plus-xpack.git
```

For the second step, in the top project, instead of adding the
dependency by installing it, run the command to link it:

```sh
xpm link @micro-os-plus/micro-test-plus
```
