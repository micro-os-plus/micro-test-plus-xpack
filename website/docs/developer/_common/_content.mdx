## Satisfy dependencies

Execute the following commands:

```sh
npm --prefix ~/Work/micro-os-plus/micro-test-plus-xpack.git install
npm --prefix ~/Work/micro-os-plus/micro-test-plus-xpack.git/tests install
xpm install -C ~/Work/micro-os-plus/micro-test-plus-xpack.git/tests
```

The last two commands install the dependencies of the tests project, such as the
build tools. The toolchains required by each build configuration are
installed later, by the `install` actions, as described in
[Manual tests](#manual-tests); those actions also run `xpm install`, so
repeating it is harmless.

## Language standard compliance

The library is written in modern C++ and should be compiled with `-std=c++20`.

## Tests

The µOS++ testing strategy involves compiling the sources with
as many toolchains as possible and executing them on a wide
range of platforms.

### Host platforms

The tests may be executed on any of the supported host
platforms:

- GNU/Linux (x64 and arm64, **GLIBC>=2.28**); to execute the native
tests, **a C++ development environment** is required
(on Ubuntu install `build-essential`)
- macOS (>= **11.0**);
as C++ development environment use **Command Line Tools**
- Windows 10, Windows 11

### Target platforms

The supported target test platforms are in the `tests/platforms` folder;
the list is taken from `tests/config/tests-templates.json`.

The test applications are executed as **native processes** on macOS and
GNU/Linux development machines with:

- `platforms/synthetic-posix`

The tests are executed as fully semihosted applications on **QEMU** emulated
boards, which can be run without any hardware, with:

- `platforms/qemu-cortex-m0`
- `platforms/qemu-cortex-m3`
- `platforms/qemu-cortex-m4f`
- `platforms/qemu-cortex-m7f`
- `platforms/qemu-cortex-m33`
- `platforms/qemu-aarch32-a15`
- `platforms/qemu-aarch64-a72`
- `platforms/qemu-riscv-rv32imac`
- `platforms/qemu-riscv-rv64imafdc`

The tests are built for **physical boards**, with the following platforms;
to run them, the board must be connected and powered up:

- `platforms/nucleo-f411re`
- `platforms/nucleo-f411re-cubemx`
- `platforms/nucleo-f411re-cubemx-startup`
- `platforms/nucleo-f767zi`
- `platforms/nucleo-f767zi-cubemx`
- `platforms/nucleo-h533re`
- `platforms/nucleo-h533re-cubemx`
- `platforms/raspberry-pi-pico`
- `platforms/raspberry-pi-pico-sdk`
- `platforms/raspberry-pi-pico-2-arm`
- `platforms/raspberry-pi-pico-2-arm-sdk`
- `platforms/raspberry-pi-pico-2-riscv`
- `platforms/raspberry-pi-pico-2-riscv-sdk`
- `platforms/raspberry-pi-zero-2-w-aarch32`
- `platforms/raspberry-pi-zero-2-w-aarch64`

Note: The Raspberry Pi Zero 2 W platform is work in progress.

The build configurations use exactly the same source files on all platforms,
without changes.

### Semihosting

On embedded platforms, the applications interact with the
host via the
[semihosting mechanism](https://github.com/ARM-software/abi-aa/blob/main/semihosting/semihosting.rst),
defined by Arm and used with the same protocol on RISC-V.

### Toolchains

To enhance source code portability, the builds are repeatedly conducted
using various toolchains, including multiple versions of the same toolchain.

The following toolchains are used:

- gcc (native)
- clang (native)
- arm-none-eabi-gcc (Cortex-M, AArch32)
- aarch64-none-elf-gcc (AArch64)
- riscv-none-elf-gcc (RISC-V 32/64)
