### Test details

The tests are built and run for each platform and toolchain. To build and run
the native tests with the system compiler, use:

```sh
xpm run test -C ~/Work/micro-os-plus/micro-test-plus-xpack.git/tests
```

The test programs are in the [`tests/sources`](https://github.com/micro-os-plus/micro-test-plus-xpack/tree/xpack-development/tests/sources) folder, one
folder for each program, with the sources in `src/`. The executables are
named `<name>-test`, and the same sources are built on all platforms.

Each program is run several times, with different options: the TAP reporter
with the default verbosity, `--verbose`, `--quiet`, and `--silent`, and the
human-readable reporter (`--reporter=human`) with the same four verbosity
levels. For each run, the tests:

- run the program;
- compare the output file with a reference file in
  [`tests/expected/tap`](https://github.com/micro-os-plus/micro-test-plus-xpack/tree/xpack-development/tests/expected/tap) or
  [`tests/expected/txt`](https://github.com/micro-os-plus/micro-test-plus-xpack/tree/xpack-development/tests/expected/txt), ignoring the program line, the
  compiler line, the timings, the addresses, and the line numbers
  (`tests/scripts/compare-files.sh`);
- parse each TAP output file with the node-tap parser, in strict mode, to
  validate it (`tests/scripts/validate-tap.mjs`).

The reference files whose names end in `-noexcept` are for the builds
without exceptions.

Some checks of the unit tests are intended to fail, to validate the
failure-reporting paths. Their failures are part of the reference outputs,
so the test passes when the output is identical to the reference file, not
when all the checks pass; the totals of the `unit` programs therefore show
failed checks.

#### The test programs

| Program | What it tests | Reference outputs |
| --- | --- | --- |
| [`empty`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/empty/src/main.cpp) | runners and suites with no checks, or with only empty test cases; it uses plain assertions instead of the framework primitives | `empty-test` |
| [`minimal`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/minimal/src/main.cpp) | the smallest possible test, a single test case with two checks, intended for first experiments | `minimal-test` |
| [`sample`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/sample/src/main.cpp) | the main primitives of the framework in a practical test, including strings, arguments passed to suites, explicit namespaces, and, if exceptions are enabled, the checks of exceptions | `sample-test` |
| [`suite`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/suite/src/main.cpp) | the test hierarchy: local runners, a static runner, and suites, including a static suite defined in a separate file, and the deeply nested test cases used to measure the stack | `suite-test` |
| [`unit`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit/src/main.cpp) | all the unit tests in one program, built from the bodies of the four programs below | `unit-test` |
| [`unit-checks`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-checks/src/main.cpp) | the expectations and requirements, the comparators, and the operands | `unit-checks-test` |
| [`unit-combinations`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-combinations/src/main.cpp) | the combinations of operand types | `unit-combinations-test` |
| [`unit-exceptions`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-exceptions/src/main.cpp) | the exceptions, including those that escape test cases and suites, and the stopped test cases | `unit-exceptions-test` |
| [`unit-miscellaneous`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-miscellaneous/src/main.cpp) | the test hierarchy, the formatters, the reporters, and the custom types | `unit-miscellaneous-test` |
| [`unit-deprecated`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-deprecated/src/main.cpp) | the deprecated operators, literals, and wrappers, built with `MICRO_OS_PLUS_MICRO_TEST_PLUS_DEPRECATED_ENABLED` | `unit-deprecated-test` |
| [`unit-static-asserts`](https://github.com/micro-os-plus/micro-test-plus-xpack/blob/xpack-development/tests/sources/unit-static-asserts/src/main.cpp) | mostly compile-time checks, with `static_assert()`; the program must compile, and is also run | none |

The `unit-checks`, `unit-combinations`, `unit-exceptions`, and
`unit-miscellaneous` bodies are also built as separate programs; their
shared header is in `unit-common`. The `unit` and `unit-checks` programs have,
besides the files for the TAP reporter, others for the console output of the
human-readable reporter (`-console` and `-console-quiet`) and for the output
with colours (`-colour`).
