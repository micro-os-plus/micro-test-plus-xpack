Detailed Description

The micro_os_plus::micro_test_plus::operators namespace provides a comprehensive set of custom operator overloads designed to enable expressive, concise, and type-safe test assertions within the µTest++ framework.

This namespace includes equality, inequality, relational, and logical operators tailored for use with the framework’s custom types. These operators facilitate the creation of clear and readable test expressions, supporting both strongly-typed constants (via user-defined literals) and dynamic values (via wrappers).

Warning
Please be aware that these operators may conflict with other operators defined within the application under test.

To minimise conflicts with application-defined operators, these overloads are enabled only when an operand is a framework expression or value wrapper (see extension::is_op). Constants typically require a literal suffix (e.g., 1_i), while dynamic values should be wrapped using the provided casting utilities (e.g., mt::to_i{...}). When neither operand is of such a type, the standard operators are selected; they return a plain bool, so a failed check cannot show the operands.

The operands are forwarded, as by the function comparators: the temporaries are moved into the returned expression, and the named operands of class type, including the nested expressions, are referred to, without copies.

There are no operators for strings and containers: the standard operators would be selected for std::string objects and for containers of the same type, and the framework operators for std::string_view objects would also replace the standard ones in the application code that follows the using directive. Use mt::eq() and mt::ne() to compare strings and containers.

All definitions within this namespace are implemented in the include/micro-os-plus/micro-test-plus folder, ensuring a modular and maintainable codebase.

Deprecated
Use the function comparators eq(), ne(), gt(), ge(), lt(), and le(), with the plain values, and all_of(), any_of(), and negate() for the logical combinations (since 5.1.0). The function comparators accept the same operands, compare them and report them in the same way, and do not need the literal suffixes or the type wrappers.
