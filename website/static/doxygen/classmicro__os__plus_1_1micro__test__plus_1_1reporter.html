Detailed Description

The reporter class is responsible for presenting test results within the µTest++ framework. It accumulates output in a buffer, using basic output operators for strings, characters, booleans, numbers, and pointers, and writes it to the console and to an optional output file.

For failed checks, the reporter prints the actual values of the operands, pre-formatted by its detail::expression_formatter (with type suffixes for numbers), supporting precise diagnostics and efficient debugging. The class supports multiple verbosity levels and colour-coded output to distinguish between successful and failed checks.

The pure virtual methods report the beginning and end of the session, the suites, and the subtests, and format the pass and fail results; they are implemented by reporter_human and reporter_tap. The concrete reporter is created by the runner, as selected by the --reporter command-line option.

All members and methods are defined within the micro_os_plus::micro_test_plus namespace, ensuring clear separation from user code and minimising the risk of naming conflicts.

This operator overload enables the reporter to output pointer values in a consistent and readable format.

Null pointers are always rendered as the string "0x0", regardless of the platform, avoiding platform-specific representations such as "(nil)" on Linux/glibc.

Non-null pointers are formatted as a hexadecimal address using snprintf with the p format specifier. The resulting string is appended to the internal output buffer, allowing pointer values to be included in test reports and diagnostics.

This approach provides clear and unambiguous representation of pointer addresses, which is particularly useful for debugging and verifying pointer-related test cases.

Writes the contents of buffer_ to output_file_ without appending a newline. If output_file_ is null, the call is a no-op.

The buffer may contain ANSI colour sequences, added when the console is a terminal, which must not reach the file. They are removed while writing: each ESC [, followed by any digits and semicolons, and terminated by m, is skipped, and the text between the sequences is written unchanged.
