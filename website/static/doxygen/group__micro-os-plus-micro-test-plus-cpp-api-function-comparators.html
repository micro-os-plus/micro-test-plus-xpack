Detailed Description

While any boolean expression can be used in expectations and requirements, dedicated comparator functions such as eq, ne, lt, le, gt, and ge provide enhanced reporting by explicitly showing the compared values when a check fails.

Using these comparators ensures that failed checks report both actual and expected values, making issues easier to diagnose.

Comparators are available for both fundamental types and standard containers. When a container comparison fails, the elements of both containers are shown.

Examples
ts.test ("Check various conditions", [] (auto& t) {
t.expect (mt::eq (compute_answer (), 42)) << "answer is 42";
t.expect (mt::ne (compute_answer (), 43)) << "answer is not 43";
t.expect (mt::lt (compute_answer (), 43)) << "answer is < 43";
t.expect (mt::le (compute_answer (), 43)) << "answer is <= 43";
t.expect (mt::gt (compute_answer (), 41)) << "answer is > 41";
t.expect (mt::ge (compute_answer (), 42)) << "answer is >= 42";
t.expect (compute_condition ()) << "condition is true";
});

If a comparator check fails, the output clearly indicates the actual and expected values:

Check failed comparisons
✗ actual != 42 FAILED (unit-test.cpp:286, 42 != 42)
✗ FAILED (unit-test.cpp:307, 42 != 42)
✗ (actual == 42) and (actual != 42.0) FAILED (unit-test.cpp:781, (42 == 42 and 42.0 != 42.0))

The C strings (char arrays, including the string literals, and char pointers) are compared by content, also with std::string and std::string_view, so mt::eq (actual, "abc") checks the characters, not the addresses; a null char pointer is equal only to another null pointer (or nullptr), not to an empty string. The other pointers and arrays (including uint8_t buffers) are compared by address.

Comparing Containers

Containers can be compared for equality or inequality using the same comparator functions. The comparison is performed with the standard == operator, so the containers must be of the same type. The standard == and != operators return a plain bool, so a failed check could not show the elements.

Examples
namespace mt = micro_os_plus::micro_test_plus;
ts.test ("Check containers", [] (auto& t) {
t.expect (mt::eq (std::vector<int>{ 1, 2 }, std::vector<int>{ 1, 2 }))
<< "vector{ 1, 2 } eq vector{ 1, 2 }";
t.expect (mt::ne (std::vector<int>{ 1, 2, 3 },
std::vector<int>{ 1, 2, 4 }))
<< "vector{ 1, 2, 3 } ne vector{ 1, 2, 4 }";
});

◆ expression_formatter

using micro_os_plus::micro_test_plus::expression_formatter = detail::expression_formatter

The function comparators and the custom operators report the values of their operands when a check fails. Values of user-defined types can be reported only if the application provides an operator<< that writes them to this formatter, declared in the namespace of the type, so that it is found by argument-dependent lookup:

namespace app
{
struct point
{
int x;
int y;
};
constexpr bool
operator== (const point& lhs, const point& rhs)
{
return lhs.x == rhs.x && lhs.y == rhs.y;
}
inline mt::expression_formatter&
operator<< (mt::expression_formatter& formatter, const point& p)
{
return formatter << "{ " << p.x << ", " << p.y << " }";
}
} // namespace app

Without such an operator, comparators such as eq() do not compile for user-defined types, since the operand values cannot be formatted; only the scoped enumerations are formatted without it, by their underlying value. Plain boolean checks, such as expect (a == b), do not need it, but they report only the source location on failure. The same operator also writes the values appended to the messages of the checks (expect (a == b) << "a is " << a).

Applications use the operator<< overloads, and str() to test their own operators; the functions that manage the buffer are private to the framework.

template<class Lhs_T, class Rhs_T, class Epsilon_T>

auto micro_os_plus::micro_test_plus::approx ( Lhs_T && lhs,
Rhs_T && rhs,
Epsilon_T && epsilon )
nodiscardconstexpr

The comparison succeeds if the distance between lhs and rhs is less than epsilon. The operands are numbers, integral or floating-point, possibly of different types, or the framework value wrappers and numeric literals, whose own tolerance is not used. For the integers, the distance is computed exactly, also for operands of different signedness, so approx (0u, -1, 2) succeeds; for the other types, in their common floating-point type. A failure is reported as lhs ~ (rhs +/- epsilon).

t.expect (mt::approx (read_adc (), 512, 3)) << "ADC reading";
t.expect (mt::approx (compute_float (), 42.0f, 0.001f));

The approx (value, epsilon) form is a value wrapper instead, which applies its tolerance to the six comparisons and to the operators; it accepts only floating-point values.

◆ eq()

template<class Lhs_T, class Rhs_T>
requires (extension::printable<Lhs_T> and extension::printable<Rhs_T>)
auto micro_os_plus::micro_test_plus::eq ( Lhs_T && lhs,
Rhs_T && rhs )
nodiscardconstexpr

The C strings (char arrays, including the string literals, and char pointers) are compared by content, also with std::string and std::string_view; a null char pointer is equal only to another null pointer. The other arrays (e.g. byte buffers) are compared element by element, also with a container, and written as ranges; the other pointers are compared by address. The pointers and arrays of char8_t, char16_t, char32_t, and wchar_t are not treated as strings: the arrays are compared element by element, including the terminating null character, and the pointers by address.

Both operands must satisfy extension::printable, since they are reported on failure; an application type needs an operator<< for mt::expression_formatter, otherwise the call is rejected, with a diagnostic that names the operand type.

The same rules apply to ne(), gt(), ge(), lt(), and le().

A comparator object that evaluates to true if the operands are equal.

The eq function template provides a generic equality comparator for any types. The operands are first passed to detail::as_operand(), which converts the C strings to detail::c_string, so that they are compared by content. It constructs a comparator object, with the detail::equal_to tag, which evaluates to true if the two values are equal, and which is reported with both values if not.

The operands are forwarded, so that the comparator moves the temporaries and refers to the named operands, without copying them.
