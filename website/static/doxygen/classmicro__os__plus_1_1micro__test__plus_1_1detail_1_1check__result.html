Detailed Description

Returned by expect() and require(), it lives until the end of the expression statement. Its template constructor evaluates the expression and formats it, with the actual operand values, into the expression formatter of the reporter, which keeps the text for this check until it is reported, so that it can be displayed on failure. The messages passed via operator<<() are collected into a string. The destructor reports the outcome, updates the counters of the test case, and, after a failed require(), stops the test case.

A passed check whose line the reporter never writes (see reporter::writes_passed_checks()) formats neither its expression nor its messages, and is only counted.

Only the template constructor depends on the type of the expression; it delegates to a private non-template constructor, and the destructor, which does the reporting, is not a template either, so this code is compiled once, in src/check-result.cpp, not for each type of expression.

Parameters

test_caseThe test case that owns this check.
expressionThe expression formatter to format the expression text.
writes_passedWhether the reporter writes the passed checks; if not, a passed check is not formatted.

The expression is evaluated, and the result is passed, together with the kind of the check and whether the expression is a framework comparator, to the non-template constructor, which also stores the source location and the test case. The kind, check_kind::requirement for require(), determines whether the test case is stopped if the check fails.

The expression formatter of the reporter, which is shared by all checks, is then assigned to this check by begin_check(), which sets aside the text of a previous check not yet reported, if any. The expression is formatted into it only when the outcome is written: on failure, or, if writes_passed, also on success. Otherwise the text of this check stays empty, and the operands, which may be application types with an expensive operator<<, are not formatted.

An expression that is only explicitly convertible to bool, such as a std::optional or a std::unique_ptr, is written as the result of the conversion, true or false, since that is what the check tested; its own value (the contents of a std::optional<bool>, for example) could contradict the outcome, and many such types cannot be formatted at all.

The decision is taken here, while the operands are alive; a result kept in a variable outlives them.

micro_os_plus::micro_test_plus::detail::check_result::~check_result ( )

It may throw failed_requirement, after a failed require(), to stop the test case, hence noexcept (false).

The destructor reports the result of the check, at the end of the expression statement, after all the user messages were appended.

The test point number of the test case is advanced first, so that the check numbers follow the order in which the checks are reported (the first check is reported as check #1), also when the result of a check is kept in a variable and reported after later checks.

If the evaluated expression is true, the reporter records a successful outcome along with any accumulated message, unless it does not write the passed checks, and the passed checks counter of the test case is incremented. If the expression is false, the reporter records a failure, with the failure details (the kind of the check, the message, and the source location) and the expression, and the failed checks counter is incremented.

The expression text is obtained from the expression formatter with check_text(), which returns the text of this check even if later checks used the formatter, and is released with end_check().

If the check is a require() and the test expression has failed, the test case is stopped: when exceptions are enabled, by throwing failed_requirement, caught by test_case::run(), as the fatal assertions of most C++ test frameworks do; the run then continues with the next test case. If the destructor runs during stack unwinding (for a result kept in a variable), it does not throw, since the test case is already being stopped.

Without exceptions, the test execution is aborted via the runner, whose reporter writes the buffered test output, in place of the end_test_case() that is never reached (see runner::abort()).

Stores the evaluated Boolean value, and, in the failure details, the kind of the check, the has_expression flag, and the location identifying the source line of the assertion, with an empty message; it also stores a reference to the owning test_case. auto & micro_os_plus::micro_test_plus::detail::check_result::operator<< ( const T & msg)
Template Parameters
TThe type of the message to append: a value that the formatter can write, or a callable object that returns one.
Parameters
msgThe message to append, or the callable object that returns it, called only if the check fails.
Returns
Reference to the current check result.

This operator overload enables the check result to accumulate expectation messages by appending the provided value to the internal message string.

The value is written by the same operator<< overloads as the operands of the expressions, so that both accept the same types, including the application types with an operator<< for the formatter. The message is moved into a local formatter in the plain mode, which writes the numbers without the type suffixes and the char values unchanged, and is moved back after the value is appended, so that no other buffer is allocated. The formatter of the reporter is not used, since it may hold the expression of this check, or of a pending one.

When the outcome of the check is not written, the message is not needed, and the value is not formatted.

A callable object (see detail::lazy_message) is called only if the check failed, and its result is appended as a value; after a success, even if the outcome is written, it appends nothing, since its purpose is to describe a failure with values that may not be valid otherwise, like the error of a std::expected that holds a value. Being a class type, a lambda without captures is called too, although it is also printable, as a bool.
