Detailed Description

counters records five counters that are maintained throughout a test session:

  • the number of checks that passed (passed_checks_),
  • the number of checks that failed (failed_checks_),
  • the number of test cases that were executed (executed_test_cases_),
  • the number of those test cases that failed (failed_test_cases_), and
  • the number of test cases skipped by the filter (skipped_test_cases_).

For a test case, the test case counters refer only to its direct nested test cases; for a suite or the runner, they refer to the test cases at all nesting levels.

The runner and every node of the test tree (suite, test_case) own a counters member and accumulate their counts in place. At the end of each suite or session the operator += propagates the child totals up to the parent node, or to the runner.

The tests can read the counters of the runner, of a suite, or of a test case through the totals() accessor.

The class is a copyable value type, so that a test can take a snapshot of the counters (counters before = ts.totals ();) and compare it later with the current values. The copy is independent: it is not updated when the original counters change. The nodes that own the live counters are themselves neither copyable nor movable. The runner returns only a const reference; the suites and the test cases also have a non-const overload, kept for v5.0.1, but the counters of the nodes are meant to be read only.
