Detailed Description

The options are usually constructed from the command line, by runner::initialise (argc, argv), which creates the selected reporter and starts the session:

tr.initialise (argc, argv);

The applications that do not have a command line, such as the embedded ones without semihosting arguments, can define the options directly, starting from the defaults:

mt::runner_options options{};
options.selected_reporter = mt::reporter_kind::human;
options.verbosity_level = mt::verbosity::verbose;
tr.initialise (options);

The applications can also parse the command line themselves, and adjust the result before passing it to the runner:

mt::runner_options options{ argc, argv };
options.list_tests = true;
tr.initialise (options);

The configuration members are public, since any combination of their values is valid; only the results of the parsing (whether errors were found, and whether the reporter was unknown) are private, and are read by the runner.

The options own their strings (the command line, the path of the output file, and the filter patterns), so they do not depend on the lifetime of the caller's strings; the runner keeps its own copy of them.

micro_os_plus::micro_test_plus::runner_options::runner_options ( int argc,
char * argv[] )
explicit

Starts from the defaults, and parses the µTest++ options (--reporter, --silent, --quiet, --verbose, --output-file, --color, --use-colour, --filter, and --list-tests). The other arguments are ignored, since the applications may define their own, except for those starting with --, which are reported as unknown options.

A missing option argument, an unknown reporter name, an unknown colour mode, or an unknown option, is reported on stderr, the option is ignored, and has_errors() is set; run() then returns

  1. The errors are not written in the report, since the reporter does not exist yet.

The argv[] strings are copied, so they need not outlive the options.

Parameters
argcThe argument count from main().
argvThe argument vector from main().
Since
5.1.0

Scans the arguments after argv[0], in order, for:

  • --reporter=<name> or --reporter <name>, with tap (the default) or human;
  • --verbose, --quiet, and --silent;
  • --output-file=<path> or --output-file <path>;
  • --color[=<when>], as in the GNU tools, with always, never, or auto (the default), and their GNU synonyms (yes and force, no and none, tty and if-tty); --color alone means always;
  • --use-colour=<mode> or --use-colour <mode>, the Catch2 and Boost UT alternative to --color, with yes, no, or auto, or any of the --color values;
  • --filter=<pattern> or --filter <pattern>;
  • --list-tests, or its short form --list, as in Catch2 and Boost UT, to list the test cases instead of running them.

When an option is repeated, the last one takes effect, except --filter, whose patterns are all kept, in order, one per nesting level; --color and --use-colour set the same option. An option argument given separately is the next argument, whatever its content; --color accepts its value only after =. The other arguments are ignored. The whole command line is copied into arguments, to be listed by the reporter; the option values are copied from there.

A missing option argument, an unknown reporter name, an unknown colour mode, or an unknown -- option, is recorded by add_error(), and the option is ignored (for an unknown reporter, has_invalid_reporter_ is also set, to stop the session in runner::initialise()); the parsing continues with the next argument.

◆ filter_patterns

std::vector<std::string> micro_os_plus::micro_test_plus::runner_options::filter_patterns {}

Each --filter=<pattern> or --filter <pattern> option adds one pattern; unlike the other options, --filter may be repeated. As with --grep in node-tap, the first pattern applies to the suite names, the second to the names of the test cases, and each further pattern to the names of the test cases nested one level deeper; the levels without a pattern are not filtered.

Within a pattern, | separates alternatives; a name matches when it matches any of them, as defined by utility::is_match(): * matches any sequence of characters, ? matches any single character, the match is case-sensitive, and the alternative must cover the whole name.

The suites and the test cases that do not match are reported as skipped, and their bodies are not called. The top suite is never skipped as a whole, since its body is main(), but when its name does not match the first pattern, all its test cases are skipped.

When the list is empty (the default), everything runs.
