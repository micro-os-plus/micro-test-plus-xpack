Detailed Description

The options are usually constructed from the command line, by runner::initialise (argc, argv), which creates the selected reporter and starts the session:

tr.initialise (argc, argv);

The applications that do not have a command line, such as the embedded ones without semihosting arguments, can define the options directly, starting from the defaults:

mt::runner_options options{};
options.selected_reporter = mt::reporter_kind::human;
options.verbosity_level = mt::verbosity::verbose;
tr.initialise (options);

The applications can also parse the command line themselves, and adjust the result before passing it to the runner:

mt::runner_options options{ argc, argv };
options.list_tests = true;
tr.initialise (options);

The configuration members are public, since any combination of their values is valid; the command line and the results of the parsing (whether errors were found, whether an unknown option was found, and where the application arguments start) are private, since they depend on one another, and are read with the accessors.

The options own their strings (the command line, the path of the output file, and the filter patterns), so they do not depend on the lifetime of the caller's strings; the runner keeps its own copy of them.

char * argv[] )
explicit

Starts from the defaults, and parses the µTest++ options (--reporter, --silent, --quiet, --verbose, --output-file, --colour, --color, --use-colour, --use-color, --filter, --list-tests, --list, --help, and -h). The parsing ends at the first argument that does not start with a dash (an application argument), or at the first -- alone; that argument, and all the following ones, are left to the application, and are available from application_arguments(). An option argument given separately (--reporter human) belongs to its option and does not end the parsing. Before that point, the arguments starting with a dash that are not µTest++ options are reported as unknown options; an application that receives such arguments first must precede them with --.

A missing option argument, an unknown reporter name, an unknown colour mode, a colour mode given separately after --colour or --color, or an unknown option, is recorded in errors(), and makes has_errors() true; the constructor writes nothing. The parsing continues, to record all the errors, but runner::initialise() then runs no test: it writes the errors on stderr, on the console, and in the output file, if any, followed, for an unknown option, by a line suggesting --help, and run_suites() returns 2.

The argv[] strings are copied, so they need not outlive the options.

Parameters

Scans the arguments after argv[0], in order, for:

  • --reporter=<name> or --reporter <name>, with tap (the default) or human;
  • --verbose, --quiet, and --silent;
  • --output-file=<path> or --output-file <path>;
  • --colour[=<when>], or its American spelling --color[=<when>], as in the GNU tools, with always, never, or auto (the default), and their GNU synonyms (yes and force, no and none, tty and if-tty); --colour alone means always;
  • --use-colour=<mode> or --use-colour <mode>, or the American spelling --use-color, the Catch2 and Boost UT alternative to --colour, with yes, no, or auto, or any of the --colour values;
  • --filter=<pattern> or --filter <pattern>;
  • --list-tests, or its short form --list, as in Catch2 and Boost UT, to list the test cases instead of running them;
  • --help, or its short form -h, to display the usage instead of running the tests.

When an option is repeated, the last one takes effect, except --filter, whose patterns are all kept, in order, one per nesting level; --colour, --color, --use-colour, and --use-color set the same option. An option argument given separately is the next argument, whatever its content; --colour and --color accept their value only after =.

The parsing ends at the first argument that does not start with a dash, or at the first -- alone; the arguments from there on are left to the application, and are not interpreted, so they can be options of the application. The -- itself is not an application argument. An argument that starts with a dash, before that point, and is not a µTest++ option, is reported as an unknown option. The whole command line is copied into arguments_, to be listed by the reporter; the option values are copied from there.

A missing option argument, an unknown reporter name, an unknown colour mode, a colour mode given separately after --colour or --color, or an unknown option (any other argument that starts with a dash, including a single one), is recorded by add_error(), and the option is ignored; the parsing continues with the next argument, to record all the errors. Nothing is written by the constructor; the runner then writes the errors and refuses to run the tests.

◆ filter_patterns

std::vector<std::string> micro_os_plus::micro_test_plus::runner_options::filter_patterns {}

Each --filter=<pattern> or --filter <pattern> option adds one pattern; unlike the other options, --filter may be repeated. As with --grep in node-tap, the first pattern applies to the suite names, the second to the names of the test cases, and each further pattern to the names of the test cases nested one level deeper; the levels without a pattern are not filtered.

Within a pattern, | separates alternatives; a name matches when it matches any of them, as defined by utility::is_match(): * matches any sequence of characters, ? matches any single character, the match is case-sensitive, and the alternative must cover the whole name.

The suites and the test cases that do not match are reported as skipped, and their bodies are not called. The top suite is never skipped as a whole, since its body is main(), but when its name does not match the first pattern, all its test cases are skipped.

When the list is empty (the default), everything runs.

Set by the --help option, or by its short form -h, which is the only short option. The runner then writes, on the console, the usage and one line for each option, runs no test, creates no output file, and run_suites() returns 0, or 2 after an option error. bool micro_os_plus::micro_test_plus::runner_options::list_tests { false }

Set by the --list-tests option, or by its short form --list. When set, the suite bodies run, as usual, to create their test cases, but the bodies of the test cases do not, so no check is evaluated.
