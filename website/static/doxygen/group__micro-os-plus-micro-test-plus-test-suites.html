Detailed Description

By default, all test cases defined in main() are included in the top-level test suite, which is owned by the runner and returned by runner::initialise(); its test cases run immediately. For more complex projects, additional test suites can be defined, typically in separate source files.

The additional test suites are either added in main() with runner::add_suite(), or defined as mt::static_suite objects, at namespace scope, constructed with a name, a reference to the runner, and a callable (usually a function or a lambda with a mt::suite& first parameter, which creates the test cases), along with any optional arguments. The static suites register themselves in their constructors, so they are included in the test run without other calls.

Important
The runner referred to by the static suites in other source files must have external linkage (not static), and be declared extern in a header shared by these files.

The static suites may be constructed before or after the runner, in any order. All suites, added or static, are run by runner::run(), after the test cases of the top suite, in a single order, sorted by name (byte by byte, as by std::strcmp()); suites with the same name run in the order in which they were created, so the static ones first. Zero-padded numeric prefixes ("01 - Init") give an explicit order. Test suites should nevertheless be designed to be independent of each other.
