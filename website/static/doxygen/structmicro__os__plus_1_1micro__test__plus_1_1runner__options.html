Detailed Description

runner::initialise (argc, argv) parses the command-line options into this structure and passes it to runner::initialise (options), which creates the selected reporter and starts the session.

The applications that do not have a command line, such as the embedded ones without semihosting arguments, can define the options directly, starting from the defaults, and call the second overload:

mt::runner_options options{};
options.selected_reporter = mt::reporter_kind::human;
options.verbosity_level = mt::verbosity::verbose;
auto& ts = tr.initialise (options, "Main");

The structure only refers to the strings it uses; they must remain valid until initialise() returns, which copies what it keeps.

◆ filter_patterns

std::vector<std::string_view> micro_os_plus::micro_test_plus::runner_options::filter_patterns {}

Each --filter=<pattern> or --filter <pattern> option adds one pattern; unlike the other options, --filter may be repeated. As with --grep in node-tap, the first pattern applies to the suite names, the second to the names of the test cases, and each further pattern to the names of the test cases nested one level deeper; the levels without a pattern are not filtered.

Within a pattern, | separates alternatives; a name matches when it matches any of them, as defined by utility::is_match(): * matches any sequence of characters, ? matches any single character, the match is case-sensitive, and the alternative must cover the whole name.

The suites and the test cases that do not match are reported as skipped, and their bodies are not called. The top suite is never skipped as a whole, since its body is main(), but when its name does not match the first pattern, all its test cases are skipped.

When the list is empty (the default), everything runs.

◆ list_tests

bool micro_os_plus::micro_test_plus::runner_options::list_tests { false }

Set by the --list-tests option, or by its short form --list. When set, the suite bodies run, as usual, to create their test cases, but the bodies of the test cases do not, so no check is evaluated. The selected test cases (see filter_patterns) are listed under the names of their suites, as Catch2 lists them:

The nested test cases are not listed, since they are created by the bodies of their parents, which do not run. The list is written to the console, unless the verbosity is silent, and to the output file, if any; no report is written, and run() returns 0, or 2 after an option error.

◆ output_file_path

const char* micro_os_plus::micro_test_plus::runner_options::output_file_path { nullptr }

Set by --output-file=<path> or --output-file <path>. When it is nullptr or empty, no file is written. The reporter opens the file, and keeps a copy of the path, when it is created by initialise(); if the file cannot be opened, the error is reported on stderr, the report is written only to the console, and runner::run() returns 2.
