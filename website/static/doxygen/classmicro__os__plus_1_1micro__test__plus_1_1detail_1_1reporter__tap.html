Detailed Description

reporter_tap provides a concrete implementation of the reporter abstract interface that formats test results according to the Test Anything Protocol (TAP). It accumulates output in an internal string buffer and writes it to the standard output stream.

The reporter is created by the runner, as selected by the --reporter command-line option, or by runner_options::selected_reporter; it is the default. A different output format requires a new class derived from reporter, and an extension of the runner to create it.

All members are defined within the micro_os_plus::micro_test_plus::detail namespace, since the reporters are internal to the framework.

Displays the buffered check results, followed by a Bail out! line with the location of the failed requirement, or of the runner::abort() call.

Parameters
locationThe source location of the failed requirement, or of the runner::abort() call.
is_requirementtrue if the abort is caused by a failed requirement.
Returns
Nothing.

Since end_test_case() is not called for the running test cases, this member function writes the buffered lines, if any, in its place (after a failed requirement, they end with it), followed by an unindented Bail out! <reason> at <file>:<line> line, with the file name escaped as the reason, which tells the TAP consumers that the run stopped early (see the TAP 14 specification), not that the output was truncated. The reason is Requirement failed after a failed requirement, and Test execution aborted for an explicit call of runner::abort().

Both are always written to the output file, as in end_test_case(), and, unless the verbosity is silent, to stdout, preceded by an empty line when add_empty_line_ is set. With quiet verbosity, which otherwise displays only the summary, they are displayed as well, since the summary is never reached.

The buffer is then cleared, so that its lines are not written again, should the abort handler throw an exception that the application catches.

Keeps the TAP stream in execution order, with the checks of the outer test case before the nested test case, as node-tap does.

Parameters
None.
Returns
Nothing.

The buffered ok/not ok lines of the outer test case are written to the output file and, with verbose verbosity, or with normal verbosity when they include a failure, to stdout, preceded by an empty line when add_empty_line_ is set. The buffer is then cleared, so that the nested test case starts with an empty buffer, and the remaining lines of the outer test case are written by its end_test_case().

With normal verbosity, the passed checks committed here are not displayed, even if the outer test case fails later; the output file always contains them.
