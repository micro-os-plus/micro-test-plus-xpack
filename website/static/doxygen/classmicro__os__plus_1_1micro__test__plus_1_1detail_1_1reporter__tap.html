Detailed Description

reporter_tap provides a concrete implementation of the reporter abstract interface that formats test results according to the Test Anything Protocol (TAP). It accumulates output in an internal string buffer and writes it to the standard output stream.

The reporter is created by the runner, as selected by the --reporter command-line option, or by runner_options::selected_reporter; it is the default. A different output format requires a new class derived from reporter, and an extension of the runner to create it.

All members are defined within the micro_os_plus::micro_test_plus::detail namespace, since the reporters are internal to the framework.

Displays the buffered check results, followed by a Bail out! line with the location of the failed requirement, or of the runner::abort() call.

Parameters
locationThe source location of the failed requirement, or of the runner::abort() call.
is_requirementtrue if the abort is caused by a failed requirement.
Returns
Nothing.

Since end_test_case() is not called for the running test cases, this member function writes the buffered lines, if any, in its place (after a failed requirement, they end with it), preceded, with normal or verbose verbosity, by the headings of the open test cases, if not displayed yet, followed by an unindented Bail out! <reason> at <file>:<line> line, with the file name escaped as the reason, which tells the TAP consumers that the run stopped early (see the TAP 14 specification), not that the output was truncated. The reason is Requirement failed after a failed requirement, and Test execution aborted for an explicit call of runner::abort().

Both are always written to the output file, as in end_test_case(), and, unless the verbosity is silent, to stdout, preceded by an empty line when add_empty_line_ is set. With quiet verbosity, which otherwise displays only the summary, the failed checks are displayed as comments, and the Bail out! line as well, since the summary is never reached.

The buffer is then cleared, so that its lines are not written again, should the abort handler throw an exception that the application catches.

Emits the TAP plan line for the test case's checks and nested test cases, followed by an ok/not ok result line that includes the test case index, escaped name, pass/fail status, and check counts. As in node-tap, the result is not ok when a check or a nested test case failed; the number of failed nested test cases is added when it is not zero. Any output accumulated in buffer_ and the two lines are always written to the output file.

With normal verbosity, a passed test case that has nothing displayed under it (no nested test case, and no committed checks) is displayed as a single test point, the ok line, without the # Subtest: heading, the plan, and the checks; this is a valid test point, and it keeps the console output short. Otherwise, with normal or verbose verbosity, the test case is displayed as a complete block, with the headings of the outer test cases first, if not displayed yet, all the buffered checks, the plan, and the result line, so that the plan matches the displayed test points, with the test point numbers unchanged. With quiet verbosity, only the failed checks are displayed, as comments (see write_quiet_failures()).

The buffer is cleared on exit.

◆ writes_passed_checks()

bool micro_os_plus::micro_test_plus::detail::reporter::writes_passed_checks ( void ) const
nodiscardnoexceptinherited

Called by test_case::expect() and test_case::require(), so that a passed check whose line is never written does not format its expression, its messages, or its line. The answer depends only on the verbosity and on the output file, which do not change during the session. A failed check is always formatted.

Parameters
None.
Return values
trueThe lines of the passed checks reach the console or the output file, at least in some cases.
falseThe descriptions and the expressions of the passed checks are never written; the TAP reporter writes only their test points (see pass_without_text()).

The passed checks are written to the output file, when it is open, whatever the verbosity; to the console only with the verbose verbosity level. With the normal verbosity, only the failed checks (with the names of the open test cases) are displayed, so the passed checks are counted, without formatting them; the TAP reporter records their test points (see pass_without_text()).
