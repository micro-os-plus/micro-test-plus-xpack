Detailed Description

In v5.0.1, the concepts, the base of the expressions, and the value wrapper templates were outside detail, in the type_traits namespace. The namespace is kept for compatibility with the existing applications: the names that still exist refer to their current definitions, in the extension and detail namespaces, and the removed helpers are restored here.

The concepts refer to the current ones, so their semantics are the current ones: is_op detects the op_type member, not the inheritance from op; has_epsilon also requires is_op; checkable also accepts the types with an explicit operator bool; printable accepts everything the formatter can print. The exception is has_value, which is not used by the framework any more, and is restored with its v5.0.1 definition.

The concepts cannot be deprecated individually, so the attribute is on the namespace. Clang reports the deprecation at every qualified use. GCC reports it only for the names declared in the namespace itself (the restored helpers and the alias templates), and, for the alias templates, only when they name the type of a declaration; it does not report the concepts, nor the names introduced by the using-declarations.

Use the concepts in the extension namespace, and extension::compare_op or extension::predicate_op for the application expressions; the value wrapper templates are internal.
