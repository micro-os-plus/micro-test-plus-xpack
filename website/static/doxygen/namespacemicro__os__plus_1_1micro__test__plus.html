Type Wrappers

Strongly-typed wrappers for converting dynamic values and expressions to specific types recognised by µTest++ comparators.

These type aliases provide a type-safe mechanism for explicitly converting values to the required types for µTest++ test expressions and comparators. Each alias is a wrapper around detail::value<T>, ensuring that the value is treated as the specified type within the framework.

The to_* forms replaced the older _i, _u8, etc. aliases, which were deprecated in version 3.2.0.

Deprecated
Pass the plain values to the function comparators eq(), ne(), gt(), ge(), lt(), and le() instead; they report the operands in the same way. For the floating-point values compared with a tolerance, use approx() (since 5.1.0).
Example
int x = 42;
// Explicitly treat x as an int for test comparison.
auto wrapped = to_i{x};

Deprecated Type Wrappers

The v5.0.1 names of the to_* type wrappers.

The Boost UT style names, with a leading underscore, kept for compatibility with the existing applications. Each one is an alias of the corresponding to_* wrapper, so the wrapped values are compared and reported in the same way. They do not conflict with the literal operators with the same suffixes (42_i), which are in the literals namespace.

GCC reports the deprecation only when the alias names the type of a declaration, not when it is used in an expression, as in _i (expr); Clang reports it in both cases.

Deprecated
Pass the plain values to the function comparators eq(), ne(), gt(), ge(), lt(), and le() instead; the to_* type wrappers that replaced these aliases (since 3.2.0) are deprecated too (since 5.1.0).

Detailed Description

The micro_os_plus::micro_test_plus namespace encapsulates all core components, types, and utilities of the µTest++ testing framework, providing a dedicated scope for its public API.

The main classes (the runners, and the suites and test cases) are defined directly in this namespace. Several nested namespaces group specific aspects of the framework: math (mathematical utilities), extension (the concepts for custom comparators, operators, and helpers), reflection (source locations and type names), literals (user-defined literals), operators (comparison and logical operators), utility (utility functions), and detail (internal implementation details, including the reporters and the value wrappers).

By grouping all definitions within this namespace and its sub-namespaces, the framework achieves clear code organisation, minimises naming conflicts, and enhances maintainability.

All public API definitions are implemented in the include/micro-os-plus/micro-test-plus folder, ensuring a clear separation from user code and facilitating straightforward integration with the wider µOS++ ecosystem.

◆ colour_mode

enum class micro_os_plus::micro_test_plus::colour_mode
strong

Selected with the --color command-line option (or its alternative, --use-colour), or with runner_options::colour; the default is automatic. The names follow the values of --color in the GNU tools.

Only the human reporter uses colours; the TAP reporter never does, since the ANSI escape sequences are not part of the TAP syntax. The output file never receives colours, whatever the mode.

Since
5.1.0
Enumerator
automatic 

Colours are used when stdout is a terminal; on the platforms without isatty(), such as the embedded ones, they are not used.

always 

Colours are always used, for example in the CI systems that render the ANSI escape sequences but do not provide a terminal, or on embedded targets whose output is displayed by a terminal.

never 

Colours are never used.

◆ verbosity

enum class micro_os_plus::micro_test_plus::verbosity
strong

The verbosity enumeration defines the available levels of detail for test output produced by the reporting system. These levels control the amount and type of information displayed during test execution, allowing users to tailor the output to their specific requirements.

The level is selected with the --silent, --quiet, and --verbose command-line options, or with runner_options::verbosity_level; the default is normal. The console output is intended for the people who watch the tests run, while the optional output file is intended for the integration with other tools. The level affects only the console output; the output file always receives the full report.

The quiet level displays the failed checks, with the names of the suite and of the test cases that contain them, and the totals; the passed checks and the passed test cases are not displayed. To also see them, use the verbose level, or keep quiet and use an output file, which receives them.

Enumerator
silent 

No console output; only the exit code is returned.

quiet 

Displays only the failed checks and the overall session summary; the TAP reporter also displays one result line per test suite, counted by the plan, and the failed checks as comments.

normal 

Displays test suite and test case results; the individual checks are shown only for failures, the passed checks being only counted.

verbose 

Displays all results, including passed checks, for maximum detail.
