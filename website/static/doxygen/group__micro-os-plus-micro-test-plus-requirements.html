Detailed Description

When a precondition of the following checks does not hold, the test case cannot continue meaningfully. A failed requirement is reported and counted like a failed expectation, and then the rest of the test case body is skipped; the run continues with the next test case.

This is the behaviour of the fatal assertions of most C++ test frameworks (ASSERT_* in GoogleTest, REQUIRE() in Catch2 and doctest, BOOST_REQUIRE() in Boost.Test). The test case is stopped with an exception; without exceptions, it cannot be stopped alone, so the results of the test case are reported, ending with the failed requirement (followed, with the TAP reporter, by a Bail out! line), and the whole test execution is aborted with runner::abort(), as Catch2 does; the remaining test cases do not run, and no totals are written.

assume() is a deprecated alias of require(); in JUnit or Hypothesis, an unmet assumption skips the test instead of failing it.

The failure is reported and counted as for expect(); then, when exceptions are enabled, the rest of the test case body is skipped, and the run continues with the next test case, as ASSERT_* in GoogleTest, REQUIRE() in Catch2 and doctest, and BOOST_REQUIRE() in Boost.Test do. Without exceptions, the test execution is aborted with runner::abort().

The test case is stopped by throwing a private exception, at the end of the statement, after the optional message was appended. It is not derived from std::exception; a catch (...) in the test case body must rethrow it, and the body must not be noexcept.

The check result evaluates the condition when constructed, records a pass or fail when it is destroyed, and, if the condition is false, stops the test case by throwing detail::failed_requirement (caught by test_case::run()), or, without exceptions, aborts the test execution.
