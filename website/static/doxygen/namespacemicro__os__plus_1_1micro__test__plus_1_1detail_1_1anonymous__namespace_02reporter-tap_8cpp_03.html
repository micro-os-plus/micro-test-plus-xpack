Detailed Description

The unnamed namespace gives the helpers internal linkage, so that they are visible only in this translation unit, and cannot conflict with the names of the application or of the other source files of the framework. They are not declared in any header.

It contains the functions that make the texts safe to write in the TAP output: tap_text(), for the test point descriptions, the reasons, and the comments, and yaml_double_quoted(), for the values of the YAML diagnostic blocks.

std::string micro_os_plus::micro_test_plus::detail::anonymous_namespace{reporter-tap.cpp}::tap_text ( std::string_view text,
bool escape )

Each line break (\\n, \\r, or the \\r\\n pair) is replaced by a space, so that the text does not end the line. When escape is true, each \\ is written as \\\\ and each # as \\#, as the TAP 14 specification recommends for the test point descriptions and the reasons, so that a # in the text does not start a directive (for example # TODO, which would hide a failure). The # Subtest: comments are not escaped, since the specification defines no escapes in comments, and the node-tap parser uses their text as it is.

◆ yaml_double_quoted()

std::string micro_os_plus::micro_test_plus::detail::anonymous_namespace{reporter-tap.cpp}::yaml_double_quoted ( std::string_view text)

The text is enclosed in ", with each \\ written as \\\\, each " as \\", and each control character (including the line breaks, the tab, and DEL) as a YAML escape sequence (\\0, \\t, \\n, \\r, \\e, and so on, or \\xHH for the others), so that the value is a single line, and is valid YAML whatever it contains. As plain scalars, the values starting with {, [, or ', or containing : or #, would be rejected or truncated by the YAML parsers used by the TAP consumers. The bytes above 0x7F are written as they are, since they are expected to be parts of UTF-8 sequences.
