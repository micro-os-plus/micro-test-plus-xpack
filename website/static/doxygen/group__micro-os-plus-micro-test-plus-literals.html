Type Wrappers

Strongly-typed wrappers for converting dynamic values and expressions to specific types recognised by µTest++ comparators.

These type aliases provide a type-safe mechanism for explicitly converting values to the required types for µTest++ test expressions and comparators. Each alias is a wrapper around detail::value<T>, ensuring that the value is treated as the specified type within the framework.

The to_* forms replace the older _i, _u8, etc. aliases, which were deprecated in version 3.2.0, and are marked [[deprecated]] since version 5.1.0.

Example
int x = 42;
// Explicitly treat x as an int for test comparison.
auto wrapped = to_i{x};

Deprecated Type Wrappers

The v5.0.1 names of the to_* type wrappers.

The Boost UT style names, with a leading underscore, kept for compatibility with the existing applications. Each one is an alias of the corresponding to_* wrapper, so the wrapped values are compared and reported in the same way. They do not conflict with the literal operators with the same suffixes (42_i), which are in the literals namespace.

GCC reports the deprecation only when the alias names the type of a declaration, not when it is used in an expression, as in _i (expr); Clang reports it in both cases.

Deprecated
Use the corresponding to_* type wrappers instead (since 3.2.0).

Detailed Description

Within test expressions, literals such as 1_i and 42_f create strongly typed operands, whilst wrappers like mt::to_i{expression} convert dynamic values. These mechanisms enable clear, type-safe comparisons, improving readability and correctness in test cases.

Literal operators, available in the dedicated literals namespace, allow constants to be expressed with explicit types, such as integers and floating-point values. For dynamic values, wrappers convert operands into recognised comparison types at run-time.

The integer literals follow the C++ syntax: decimal, hexadecimal (0x10_i), binary (0b101_i), and octal (010_i, which is 8), with digit separators (1'000_i). A decimal point, an exponent, or a value that does not fit in the type of the literal (e.g. 300_u8) is a compilation error.

The floating-point literals are written with decimal digits and a decimal point, optionally with digit separators (1'000.000'5_d), but without an exponent; they can have up to 19 digits before the decimal point and 19 after it, otherwise the compilation fails.

The floating-point literals (1.5_d) and wrappers (mt::to_d{ 1.5 }) compare with a tolerance of one unit of the last decimal written (0.1 for 1.5), so that 1.45 == 1.5_d is true. All six comparisons apply it consistently: values within the tolerance are equal, and neither less nor greater. Plain floating-point values compare exactly. To set the tolerance explicitly, independent of how the value is written, use mt::approx (1.5, 0.01).

This approach ensures that both compile-time constants and run-time values can be compared accurately and expressively, supporting robust, maintainable test code.

Examples
namespace mt = micro_os_plus::micro_test_plus;
ts.test ("Check typed operands", [] (auto& t) {
using namespace mt::operators;
using namespace mt::literals;
t.expect (mt::to_i {answer} == 42_i);
t.expect (mt::to_f {expression} == 42_f);
});

◆ approx()

template<class T>
requires std::is_floating_point_v<T>
auto micro_os_plus::micro_test_plus::approx ( T value,
std::type_identity_t< T > epsilon ) -> detail::value< T >
nodiscardconstexprnoexcept

Constructs the floating-point detail::value<T> with the given tolerance, instead of the one derived from the number of decimals of the value.

The floating-point literals (1.5_d) and wrappers (to_d{ 1.5 }) compare with a tolerance derived from the number of decimals written (0.1 for 1.5). approx() makes the tolerance explicit, independent of how the value is written. All six comparisons apply it: values whose difference is less than the tolerance are equal, and neither less nor greater. If both operands have a tolerance, the smaller one is used.

t.expect (mt::eq (compute_float (), mt::approx (42.0f, 0.001f)));

For a single comparison, also of integers, the approx (lhs, rhs, epsilon) function comparator may be used instead.

Template Parameters
TThe floating-point type of the value.
Parameters
valueThe expected value.
epsilonThe tolerance, converted to T.
Returns
A detail::value<T> wrapper, recognised by the comparators and the operators.

5.1.0

◆ operator""_b()

auto micro_os_plus::micro_test_plus::literals::operator""_b ( const char * name,
decltype(sizeof("")) size )
nodiscardconstexpr

This user-defined literal operator creates a named boolean constant, with the value true, from a string literal (for example, "feature_enabled"_b).

The returned detail::named_bool converts implicitly to bool, and the expression formatter prints its name instead of its value. With the operators in the operators namespace, a comparison like "feature_enabled"_b == flag is true when flag is true, and, when it fails, it is reported as feature_enabled == false; the same applies to eq ("feature_enabled"_b, flag). Without these operators, the comparison is a plain bool expression, and its operands are not reported.

Parameters
namePointer to the character sequence representing the literal.
sizeThe size of the character sequence.
Returns
A detail::named_bool instance, with the value true, reported by its name.
