Detailed Description

suite represents a top-level named group of related test cases within the µTest++ framework. It is created by calling runner::add_suite(), which constructs the object and stores it in the runner's collection; the stored suites are run later by runner::run(), together with the static suites, sorted by name. Each suite records its own timing information and propagates its results to the owning runner.

The suites to be run, registered or static, are kept in a single list, sorted by name, which does not depend on the runner object: its head is a constinit pointer, initialised before any constructor runs, and the links are members of the suites. The list includes the suites of all runners; each runner runs those that refer to it, in the order of the list.

The body of a suite is supplied as a callable (typically a lambda) that receives a suite& reference as its first argument. Inside the body, suite::test() is called to create and run individual test cases.

The constructor is protected, since a suite constructed elsewhere would not be registered with the runner; the suites are created only by runner::add_suite(), by the derived static_suite, which registers itself, and by the runner, for its top_suite.

The class is non-copyable and non-movable to preserve unique ownership and consistent state throughout the test session.

suite & suite )
protectedinherited

The child test case is a local object of create_test_case(), and is destroyed when that function returns.

Parameters
test_caseThe newly created test_case.
suiteThe parent suite to which execution results are reported.
Returns
Nothing.

Counts test_case, which is a local object of the calling create_test_case(), and immediately invokes test_case::run() on it. The test case is not kept; only child_test_cases_count_ is needed later, for the TAP plan.

If the filter patterns do not select the test case (its own name at its nesting level, or the name of suite at level 0, which matters only for the top suite, since the other suites run only when selected), its body is not called: the reporter is notified with skip_test_case() and the parent's skipped test cases counter is incremented. The test case keeps its index and its place among the children, so the TAP plan of the parent remains complete.

Otherwise, while the test case runs, the runner keeps it as its innermost running test case (see suite::test()). The parent's executed test cases counter is incremented after the run, and, if the child failed (a failed check, or a failed nested test case), its failed test cases counter too, so that the parent fails as well, as in node-tap. The child's check counters are intentionally not merged into the parent totals; each test case reports only its own counters. The child's totals are, however, accumulated into suite so that the suite summary reflects all checks performed by its test cases.

While the test cases are listed (see runner_options::list_tests), the selected test case is listed by the runner, and neither run nor counted, except in child_test_cases_count_.

After the test execution was aborted (possible only when the abort handler threw an exception, which the application caught), the report is complete, so the test case is neither run nor reported.

The common body of suite::test() and test_case::test(), which differ only in the parent suite and the nesting depth of the test cases they create.

Always inlined into them, even without optimisations, since each nested test case adds one call chain to the stack, and a separate frame for this function would make it longer.

Template Parameters

Args_TThe types of the callable arguments.
Parameters

parent_suiteThe suite to which the test case belongs.
nesting_depthThe depth of nesting of the test case; 1 for the direct children of a suite.
callableA generic callable object, usually a lambda, invoked to perform the test.
argumentsA possibly empty list of arguments to be passed to the callable.
Returns
Nothing.

Binds the callable and its arguments into a local body, constructs the child test_case as a local object that refers to the body, with the next test point number of this node as its index, then passes it to after_test_case_create(), which counts and runs it.

The child test case and its body, with the copies of the arguments, are destroyed when this function returns, so the memory used by a test session does not grow with the number of test cases; the stack holds one test case and one body for each level of nesting being run. Since the body is not stored in a std::function, it is never allocated, whatever the size of the lambda captures and of the arguments.

The test function template creates a test case (a test_case with nesting depth 1) and runs it immediately. It accepts a descriptive name, a callable object (such as a lambda or function pointer), and an optional list of arguments to be passed to the callable, after the leading test_case& reference. The test case is reported using the provided name.

The test case is created and run by create_test_case(), as a local object destroyed when it returns, together with its stored body and bound arguments; only the number of test cases is kept, for the TAP plan.

Each test case typically involves evaluating logical expressions, such as comparing a computed result to an expected value, with expect() or require(). When exceptions are enabled, it is also possible to verify whether evaluating an expression throws exceptions. Each check either passes or fails, and the suite totals count the passed and failed checks.

It is typically invoked within the body of a suite. When invoked from the body of a running test case (for example via a captured suite reference), the new test case could not be reported as a sibling of the running one, which has not ended; it is therefore created by the innermost running test case, with test_case::test(), and runs nested in it, as if test() had been called on that test case.

Example
namespace mt = micro_os_plus::micro_test_plus;
ts.test ("Check answer with comparator", [] (auto& t) {
t.expect (mt::eq (compute_answer (), 42)) << "answer is 42";
});
