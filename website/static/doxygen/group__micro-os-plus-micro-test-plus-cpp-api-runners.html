Detailed Description

A test program has one runner, usually a global object, which main() uses in three steps:

  1. initialise (argc, argv) reads the command-line options (see Command-Line Options); on platforms without a command line, initialise (runner_options) sets the options directly. The call is optional; without it, the default options are used;
  2. add_top_suite() returns the top suite, on which main() creates its own test cases (see Test Suites). The call is optional, for programs whose test cases are all in other suites;
  3. run_suites() runs the other suites, writes the totals, and returns the exit code, which main() returns to the system.

The exit code is:

  • 0 when all the checks passed, or when the test cases were only listed;
  • 1 when a check failed, or when the program used the runner wrongly (for example, it added no suite at all);
  • 2 when the command line had an error, or when the filters selected no test case.
Example
#include <micro-os-plus/micro-test-plus.h>
namespace mt = micro_os_plus::micro_test_plus;
mt::runner tr;
int
main (int argc, char* argv[])
{
tr.initialise (argc, argv);
auto& ts = tr.add_top_suite ("Minimal");
ts.test ("Check truth", [] (auto& t) {
t.expect (true);
});
return tr.run_suites ();
}

The program writes (the passed checks are displayed only with the --verbose option):

# Running: minimal
# Built with ...
TAP version 14
# Subtest: Minimal
ok 1 - Check truth # { passed, 1 check }
1..1
ok 1 - Minimal # { passed, 1 check in 1 test case, time: 0.039 ms }
1..1
# { total: 1 check passed, 0 failed, in 1 test case, 1 test suite, time: 0.074 ms }

The name of the top suite is optional. Without it, the suite is named after the program, the file name of argv[0] without its extension (minimal above); without argv[0], it is named default suite.
