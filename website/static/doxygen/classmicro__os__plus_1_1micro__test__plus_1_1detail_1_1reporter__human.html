Detailed Description

reporter_human provides a concrete implementation of the reporter abstract interface, formatting and presenting test results in a human-readable form. It accumulates output in an internal string buffer and writes it to the standard output stream, supporting colour-coded diagnostics (when the output is a terminal, or when forced with --color) and multiple verbosity levels.

The reporter is intended for the people who read the console output. Most writes to the optional output file follow the console verbosity, so the file receives the full report only with normal or verbose verbosity; for the integration with other tools, the TAP reporter, whose output file is always complete, is the one to use.

The reporter is created by the runner, as selected by the --reporter command-line option, or by runner_options::selected_reporter. A different output format requires a new class derived from reporter, and an extension of the runner to create it.

All members are defined within the micro_os_plus::micro_test_plus::detail namespace, since the reporters are internal to the framework.

Displays the names of the open test cases not yet displayed, followed by the buffered check results, and a final ✗ Test execution aborted at <file>:<line> line, in place of the totals.

Parameters
locationThe source location of the failed requirement, or of the runner::abort() call.
is_requirementtrue if the abort is caused by a failed requirement.
Returns
Nothing.

Since end_test_case() is not called for the running test cases, this member function writes the buffered results in its place; after a failed requirement, they end with it. As in end_test_case(), they are written to the output file only with normal or verbose verbosity.

Unless the verbosity is silent, the names of the open test cases that were not displayed yet (all of them, with normal or quiet verbosity) are written to stdout, followed by the buffered results, so that a failure is not attributed to the previous test case. With quiet verbosity, which otherwise displays only the summary, the results are displayed as well, since the summary is never reached; this includes the passed checks, which give the context of the failure.

In place of the summary, a ✗ Test execution aborted at <file>:<line> line is then written, as the summary is, unless the verbosity is silent, to the output file and to stdout. After a failed requirement, the location is the same as in the failure line, which is already marked - test execution aborted; for an explicit call of runner::abort(), it is the only report of the abort.

The buffer is then cleared, so that its results are not written again, should the abort handler throw an exception that the application catches.
