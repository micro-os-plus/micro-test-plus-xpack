Version **6.0.1** is a maintenance release. The library is unchanged; the
release adds programs that measure the memory footprint of µTest++ and of the
compared testing frameworks, gives the results on the website, and updates
the tests.

The [µTest++ Testing Framework](https://micro-os-plus.github.io/micro-test-plus-xpack/)
project is a C++ source code library that provides a macro-free testing framework for embedded systems.

<CommonPrerequisites nodeVersion="22.12"/>

## Installation

The most convenient way to integrate the `@micro-os-plus/micro-test-plus`
package into a project is to add it as a dependency with **xpm**.

<CodeBlock language="console"> {
`xpm install @micro-os-plus/micro-test-plus@${frontMatter.version} --verbose
`} </CodeBlock>

However, like any source code library, this project can also be
integrated into another project in the traditional manner, either
by copying the relevant files into the target project or by
linking the entire project as a Git submodule.

Detailed instructions are available in the [Integration Guide](/docs/install/).

## Bug fixes

## Enhancements

- [[#290](https://github.com/micro-os-plus/micro-test-plus-xpack/issues/290)]: The tests create a listing for every executable by default
- [[#291](https://github.com/micro-os-plus/micro-test-plus-xpack/issues/291)]: The tests do not measure the footprint of the other frameworks
- [[#292](https://github.com/micro-os-plus/micro-test-plus-xpack/issues/292)]: The website claims a small footprint without any figures

The footprint of a minimal test program, built with µTest++ and with Unity,
CppUTest, doctest, Catch2, Boost UT, Boost.Test, GoogleTest, and snitch, on
nine QEMU platforms, is given in the
[comparison with other frameworks](/docs/getting-started/comparison/#footprint);
on a Cortex-M4F, the µTest++ program adds 46 KiB of flash to an empty
program (81 KiB), against 102 KiB with CppUTest, and 354 to 507 KiB with
Boost UT, doctest, GoogleTest, snitch, Boost.Test, and Catch2. The same page
now also compares µTest++ with snitch.

Other changes, in the tests only:

- the session check of the unit programs expects the exit code 1 after the
  rejected second calls of `initialise()` and `add_top_suite()`;
- the `nucleo-f411re-cubemx-startup` platform defines the size of the
  semihosting command line buffer, which was too short for the
  `unit-combinations` test.
