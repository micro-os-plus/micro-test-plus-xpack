# Website API reference review

Date: 2026-11-02, on branch `xpack-development`, commit `90eed7fe`.

Scope: the pages under `website/docs/api/` and the sources they are
generated from (the Doxygen comments in `include/` and `src/`, and the
hand-written sources in `website/doxygen/`: `topics.h`, `pages/`,
`files/`, `folders/`, `macros/`, `topics/`, and `topics/cpp-api/`, with
the Doxygen configuration and the sidebar JSON). The rest of the website
is in WEBSITE-REVIEW.md, the API design in API-REVIEW.md.

Method: the pages are fresh (regenerated in the last commit, no later
change to `include`, `src`, or `website/doxygen`). Doxygen 1.18.0 with
`EXTRACT_ALL = NO` and the strict `WARN_*` options: 0 warnings;
`check-doxygen-merged.mjs`: 0 problems; `check-doxygen-style.mjs`: 3 long
lines (`deprecated.h` lines 800, 818, and 839). Doxygen prints the
obsolete-tag warning of #9 (and, only in the strict check, a second one
for `SITEMAP_URL`, which the project configuration does not trigger).
The site built successfully with `docusaurus build`, with no
broken-link or broken-anchor message. Every
example of the topics was compiled with `clang++ -std=c++20 -Wall
-Wextra -Wshadow` (Apple clang 17) and run, together with probes of the
claims about the comparators, the `all_of()`/`any_of()` functions, the
requirements, and the command line options; the sample outputs were
compared with the output of `tests/sources/minimal` built the same way.
Not done: the Doxygen comments of the individual classes and members
were checked only with the automatic checks and by reading the class
page of `runner`, not one by one against the code; the earlier reports
(API-REVIEW.md and WEBSITE-API-REVIEW-1.md) were not read.

Summary: 28 problems (4 open, 23 fixed, 1 needing no change, 0
withdrawn). The most serious were the stale sample outputs in the topics
(#2, #3, #4, #27), the false statements about `topics.h` (#7), and the
garbled backslash (#1). All the defects, the missing information, the
readability of the topics (#25, #26), and the consistency items are
done. The four open items (#18 to #21) are decisions for the maintainer
about the presentation; the API design decision (#19) comes last.
Regenerate the pages at the end.

## Note on generated pages

Every page under `website/docs/api/` is generated by `npm run
generate-website-doxygen` in `website/` (Doxygen, then
doxygen2docusaurus) and must not be edited. Each item names the source to
change, marked as **[topic]** (a hand-written source in
`website/doxygen/`), **[header]** (a Doxygen comment in `include/` or
`src/`), **[config]** (a Doxygen configuration file), **[template]**
(`top-common.h`, from `@xpack/docusaurus-template-liquid`),
**[converter]** (`@xpack/doxygen2docusaurus`), or **[code]** (a change to
the library).

## 3. Structure and presentation

- **#18 — The pages are very large.** [config]
  `common-config.doxyfile` sets `INLINE_SOURCES = YES`,
  `SOURCE_BROWSER = YES`, `REFERENCES_RELATION = YES`,
  `REFERENCED_BY_RELATION = YES`, and `INLINE_INHERITED_MEMB = YES`
  (the original configuration has them all `NO`). The result is 13 MB in
  225 pages; the largest are `reporter-tap` (666 KB), `reporter-human`
  (640 KB), `deprecated.h` (495 KB), `expression-formatter` (489 KB),
  and `runner` (414 KB), for classes of a few hundred lines. Switch off
  `REFERENCES_RELATION` and `REFERENCED_BY_RELATION` first, then
  `INLINE_SOURCES`, and compare the sizes. This is a decision for the
  maintainer, since the inlined definitions are used for navigation.

- **#19 — Internal entities are mixed with the public ones.** [config]
  The Classes hierarchy has 45 entries at one level, the public `runner`,
  `suite`, and `test_case` among `callable_result`, `colour_code`,
  `tap_name`, `identity`, `list`, and the `function_traits`
  specialisations; the Concepts index lists 18 `detail` concepts against
  11 in `extension`. Options: exclude `detail` from the sidebar
  hierarchy (`EXCLUDE_SYMBOLS`, with the documented types that the public
  signatures need kept), or add a separate "Internal" category in the
  sidebar. Decision for the maintainer.

- **#20 — The topic tree is deep and its order does not follow the
  reader's task.** [topic] `topics.h` lines 42 to 51 order the topics as
  runners, test cases, expectations, requirements, comparators, logical
  functions, exceptions, utilities, suites, deprecated. The suites come
  after the utilities, although a reader meets them right after the
  runner; and the path to the first content is four levels (µOS++ Topics,
  µTest++, C++ API, topic). See section 7 for the proposed moves.

- **#21 — Documentation-only files are published as library files.**
  [config] The Files index and the pages `files/top-common-h.md` and
  `files/topics-h.md` present `top-common.h` and `topics.h` next to the
  headers. Exclude them with `EXCLUDE`, or keep `topics-h` as the single
  page that explains the topic sources (#7) and remove `top-common.h`.

  Runners" (line 42), so that the order is runners, suites, test cases,
  expectations, requirements, comparators, logical functions, exceptions,
  utilities.
- **Move B.** Merge "Expectations" and "Requirements" into one topic
  "Checks" (two topics with one function each and 14 to 18 lines of
  text); keep the two anchors for existing links.
- **Move C.** Add the "Customisation" topic of #16 after the logical
