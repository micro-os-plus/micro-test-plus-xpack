# stm32cubemx/README

## STM32CubeMX

This content of this folder is generated by STM32CubeMX.

The configuration is stored in `stm32cubemx.ioc` and the content can
be updated at any time.

## Customisations

The code gnerated by STM32CubeMX provides a simple, but functional startup
and main. To accomodate for a more elaborate initialisation logic and for
a main() function located in the application, there are some customisations 
to be done.

Fortunately, STM32CubeMX uses some `USER CODE` sections, that are not
overitten when regenerating code.

### `Core/src/main.c`

There are several customisations done to main:

- wrap `main()`
- wrap `__libc_init_array()`
- rename as `micro_os_plus_startup_initialise_hardware_hook()`

```c
/* Private user code ---------------------------------------------------------*/
/* USER CODE BEGIN 0 */

int micro_os_plus_startup_initialise_hardware_hook (void);
void micro_os_plus_startup_run_main(void);
int __wrap_main(void);
void __wrap___libc_init_array(void);

// Trick to intercept the call from _start(), since we need to do a
// little bit more than STM32CubeMX initialization.
int __wrap_main(void)
{
  micro_os_plus_startup_run_main();

  while (1) {
    __WFI(); // Wait For Interrupt
  };
}

void __wrap___libc_init_array(void)
{
  // Silence this call, the static initializers will be called in the 
  // µOS++ startup code.
}

// ----------------------------------------------------------------------------

// Turn the main function into the hardware initialization hook.

// Mind the fact that the `while` loop at the end is commented out 
// and the function returns 0.

#define main micro_os_plus_startup_initialise_hardware_hook

/* USER CODE END 0 */
```

### `stm32f4xx_it.c`

The SysTick handler is not generated by STM32CubeMX and must be added
manually:

```c
/* USER CODE BEGIN 1 */

void SysTick_Handler(void)
{
  HAL_IncTick();
}

/* USER CODE END 1 */
```

## CMake

The definitions generated by STM32CubeMX are used in `device/CMakeLists.txt`,
but not directly, they require a relatively elaborate hack to extract them
and reuse in a more apropriate set of libraries, consistent with the
rest of the µOS++ projects.

## Memory map

The memory map is copied from `stm32f411xe_FLASH.ld` into
`device/linker-scripts/mem.ld`

## SVD

For debugging purposes, the `STM32F411xx.svd` file was added locally.

It was generated vy Claude, from the file provided by STM in the STM32F4xx_DFP
package and the `armv7m-system-peripherals.svd` available in the 
`architecture-cortexm` package.
